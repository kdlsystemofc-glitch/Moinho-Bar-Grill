# KDL REFERENCE-FIRST LANDING METHODOLOGY

## Visual Fidelity Manifesto

Version 3.0

---

# PURPOSE

This project uses a REFERENCE-FIRST methodology.

The objective is not to ask AI to invent a website inspired by another website.

The objective is to create an original client website using a supplied reference as a concrete structural, compositional and experiential target.

The final result must preserve the client's identity and content while reaching the visual sophistication demonstrated by the reference.

---

# AUTHORITY HIERARCHY

There are THREE primary sources of truth.

## 1. CLIENT MATERIAL = CONTENT TRUTH

Client files define:

- business information
- products
- services
- address
- contacts
- photographs
- logo
- brand identity
- factual claims

Never invent missing facts.

---

## 2. REFERENCE SCREENSHOT = VISUAL TRUTH

The file:

referencia/reference-full.png

is the PRIMARY VISUAL AUTHORITY.

It defines the target for:

- page silhouette
- proportions
- composition
- section rhythm
- whitespace
- density
- typography scale relationships
- image scale
- visual hierarchy
- color-field behavior
- viewport occupation
- alignment
- overlap
- scene transitions
- visual complexity

Do not reinterpret its structure into a generic template.

---

## 3. REFERENCE URL = BEHAVIOR TRUTH

The URL stored in:

referencia/reference-url.txt

must be inspected whenever accessible.

It defines the target for:

- interaction
- navigation behavior
- hover behavior
- scroll choreography
- animation
- sticky behavior
- parallax
- transitions
- responsive behavior
- motion timing
- microinteractions

---

# MAIN PRINCIPLE

REFERENCE STRUCTURE
+
CLIENT CONTENT
+
CLIENT IDENTITY
=
FINAL EXPERIENCE

NOT:

REFERENCE
→ "inspiration"
→ AI creates whatever it prefers.

---

# REFERENCE IS NOT A MOODBOARD

The reference is not merely a source for:

- colors
- fonts
- feelings
- vague adjectives

It is a concrete compositional benchmark.

The AI must study:

- what occupies each viewport
- where visual masses appear
- how large elements are relative to viewport
- how sections begin and end
- how images interact with typography
- how whitespace behaves
- where the layout breaks its own grid
- where motion changes the experience
- how mobile differs from desktop

---

# FIDELITY BEFORE DIVERGENCE

Do not attempt originality by immediately changing the structure.

First achieve strong structural fidelity.

Only after the architecture works may client-specific identity create divergence.

The client adaptation should change:

- branding
- content
- imagery
- colors where appropriate
- typography where appropriate
- graphic motifs

It should NOT destroy:

- structural sophistication
- visual rhythm
- scene proportions
- interaction complexity
- image participation
- motion architecture

---

# NO CATEGORY FALLBACK

Never transform a reference into a category template.

Restaurant does NOT automatically mean:

- text + food photo
- menu cards
- testimonial cards
- map block
- black + gold
- beige + orange
- 3-column food grid

Bar does NOT automatically mean:

- black
- condensed font
- orange
- giant headline
- rectangular food photos

The reference has priority over category clichés.

---

# SCREENSHOT SILHOUETTE LOCK

Before implementation, reconstruct the visual silhouette of the reference.

For every major visual chapter identify:

- approximate height
- width
- dominant mass
- image position
- typography position
- background
- whitespace
- alignment
- overlap
- transition

Once approved, this silhouette becomes LOCKED.

Do not replace it during implementation because another layout is easier.

---

# STRUCTURAL EQUIVALENCE

Client content must be mapped to structural roles.

Example:

REFERENCE:
large hero product

CLIENT:
strongest real client visual

REFERENCE:
product selection scene

CLIENT:
relevant client products/services

REFERENCE:
brand story scene

CLIENT:
client story/environment/location

The semantic content may change.

The visual function should remain comparable.

---

# DO NOT COPY BRAND IDENTITY

Never copy:

- logo
- brand name
- original copy
- proprietary illustrations
- original photography
- trademarked visual assets
- original product packaging

Use the reference as structural and experiential guidance.

---

# PHOTOGRAPHY ADAPTATION

If client assets do not naturally fit a reference slot:

ADAPT THE ASSET.

Do not abandon the reference structure immediately.

Allowed techniques:

- crop
- background removal
- masks
- subject isolation
- composite photography
- image extension
- layering
- object-position
- controlled overflow
- photographic blending

Original files must remain preserved.

---

# TYPOGRAPHIC FIDELITY

Typography may use a different legal font family.

However preserve important geometry such as:

- scale contrast
- relative width
- line breaks
- weight relationships
- density
- alignment
- visual dominance

Do not reduce oversized reference typography to normal website headings.

---

# COLOR

Client identity may alter colors.

But preserve the reference's COLOR BEHAVIOR.

Example:

If the reference uses:
large color fields
→ client version must also use meaningful large visual fields.

If the reference changes atmosphere throughout scroll
→ client version should preserve comparable chromatic rhythm.

---

# MOTION

Motion is part of structural fidelity.

Do not replace reference motion with universal fade-up animations.

When relevant study and recreate equivalent behavior using:

- GSAP
- ScrollTrigger
- Lenis
- CSS animation
- clip-path
- masks
- transform
- sticky
- horizontal scrolling
- parallax
- scale
- typography motion

Always support prefers-reduced-motion.

---

# MOBILE

Mobile must be compared against the reference mobile experience whenever possible.

Never automatically stack desktop.

Preserve:

- identity
- composition logic
- hierarchy
- visual rhythm
- key signature mechanisms

# IMPLEMENTATION RULE

The AI is NOT allowed to change an approved structure merely because another implementation is easier.

If a reference mechanism is difficult:

solve the implementation problem.

Do not replace it with:

- card
- grid
- split section
- centered container

without explicit human approval.

---

# SCREENSHOTS ARE EVIDENCE

Written self-evaluation is not evidence.

"PASS"
"Outstanding"
"Premium"
"100/100"

have no authority without visual proof.

The actual rendered screenshots are the source of truth.

---

# VISUAL COMPARISON

Every implementation phase must compare:

REFERENCE
vs
CLIENT IMPLEMENTATION

Compare:

- silhouette
- scale
- density
- visual masses
- image participation
- typography participation
- whitespace
- color rhythm
- section rhythm
- viewport usage
- motion
- responsive behavior

---

# FAILURE CONDITIONS

The project fails if:

1. The final page follows a generic category template.

2. The screenshot reference and implementation have materially different silhouettes without justified client constraints.

3. Reference image behavior becomes simple card imagery.

4. Reference typography becomes conventional headings.

5. Reference motion disappears.

6. Multiple distinct references would all lead to approximately the same implementation.

7. The final result could have been created without ever seeing the supplied reference.

---

# NO SELF-APPROVAL

The AI may identify technical issues.

The AI cannot provide final visual approval.

Only HUMAN VISUAL REVIEW approves:

- Hero
- structural fidelity
- complete page
- final production direction
